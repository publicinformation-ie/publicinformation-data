# COFOG 1999 vocabulary

The United Nations' [Classification of the Functions of Government
(COFOG)](https://unstats.un.org/unsd/classifications/Econ/Download/In%20Text/COFOG_english_structure.txt)
1999 edition, published as an open vocabulary. It classifies government
functions in ten divisions, each split into groups and classes — 188 terms in
total — and PublicInformation.ie uses it for agenda-item topics in the
[SPC meetings dataset](../latest/spc-meetings/README.md).

## Structure

- **Division** (`01`–`10`): a major area of government function, such as
  `04` "Economic affairs" or `07` "Health".
- **Group** (`04.5`): a subdivision of a division, such as `04.5` "Transport".
- **Class** (`04.5.1`): the finest level, such as `04.5.1` "Road transport".

Every class also states whether it describes a **collective** or an
**individual** service, which the UN source marks `(CS)` or `(IS)`. For
example, `04.5.1` "Road transport" is a collective service, while `07.1.1`
"Pharmaceutical products" is an individual one. Divisions and groups carry no service
type.

This publication carries labels and hierarchy only. The authoritative
definitions are the UNSD explanatory notes, which are not reproduced here.

## Term URIs

Every term has the URI
`https://data.publicinformation.ie/ns/cofog#<code>` — for example
[`https://data.publicinformation.ie/ns/cofog#04.5.1`](https://data.publicinformation.ie/ns/cofog#04.5.1).
The namespace base resolves to a human-readable page at
[`https://data.publicinformation.ie/ns/cofog/`](https://data.publicinformation.ie/ns/cofog/),
which lists the divisions and every distribution.

This namespace means COFOG 1999 and will keep meaning it: when the UN's
revised classification (expected by 2028) is published here, it gets a new
namespace and a new vocabulary, and these URIs will not change meaning.

## Formats

| Format | File | Use it for |
|---|---|---|
| JSON | [cofog-1999.json](cofog-1999.json) | The scheme metadata, the nested divisions → groups → classes tree, and a flat `concepts` index keyed by code. Each class carries its `service_type`. |
| CSV | [cofog-1999.csv](cofog-1999.csv) | Spreadsheets and joins: one row per term with `uri`, `notation`, `name` and `description`, described by [cofog-1999.csv-metadata.json](cofog-1999.csv-metadata.json) (CSVW). |
| Turtle | [cofog-1999.ttl](cofog-1999.ttl) | Linked data: one `skos:ConceptScheme` and one `skos:Concept` per term, with `skos:broader` hierarchy and a `skos:scopeNote` on each class naming its service type. |

The three files describe the same 188 concepts. The CSV keeps the four-column
shape every vocabulary on this site uses; it does not carry parent, level or
service type — join through `notation` to the JSON, or use the Turtle.

> `5368887bb253a1819bfefc6a9eedc74cb76f50c6a7c35133d2420b1d4a3b39b5`.

The pinned source copy is
`pipelines/spc_pipeline/reference/cofog_1999.json`, refreshed by
`pipelines/spc_pipeline/scripts/build_cofog.py`, which records the source URL,
retrieval date and sha256, treating a changed sha256 as a reviewed content
change. The scheme metadata in the JSON and Turtle repeats the
source URL, retrieval date, sha256 and version.

## Regenerating

The four files are generated by one script; never edit them by hand.

```bash
uv run python scripts/build_cofog_vocabulary.py           # write all four
uv run python scripts/build_cofog_vocabulary.py --check   # verify, write nothing
```

A write run changes files, and restamps `dct:modified` in
[`../catalog/dataset-cofog-1999.ttl`](../catalog/dataset-cofog-1999.ttl), only
when a distribution's bytes change.

`--check` exits non-zero and names any file that differs from what the pinned
reference produces. The generator validates the reference (complete
provenance, unique codes, known parents, 10 divisions / 69 groups / 109
classes) and writes nothing when validation fails.

## Versioning

The classification version is `1999` (`owl:versionInfo` in the Turtle,
`version` in the JSON). The published files are unversioned — there is no
`latest/` or release copy, as with every vocabulary on this site — because the
underlying classification does not change. A future COFOG revision is a new
vocabulary under a new namespace, not an update to these files.
