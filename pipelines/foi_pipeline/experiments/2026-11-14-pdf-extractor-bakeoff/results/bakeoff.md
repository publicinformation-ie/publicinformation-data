# PDF extractor bake-off results

Generated by `report.py` from `results/bakeoff.json` (`bakeoff.py`). 36 sample PDFs x 7 extractors; gold set = 10 PROVISIONAL files (not user-spot-checked). **N is small**: 10 gold files, 67 (candidate, gold file) pairs of which many are near-duplicates (pdfplumber and pdfplumber_lines are identical: pdfplumber's default strategy is already `lines`; several extractors return the same rows on easy files).

Gold accuracy = share of gold cells matching exactly at the same column index in the best-aligned candidate row (alignment key = first reference cell, else first date cell). `raw` = whitespace-normalised only; `norm` also maps U+F0B7 to U+2022 and removes the space in hyphen-space joins, on both sides. The gold covers only the first 15 and last 5 data rows, so damage in the middle of a file is invisible to it.

### Calibration reasoning

- Starting point: the literal rule (tightest values passing every candidate with gold >= 0.95) gives width >= 0.526 and fragment <= 0.51, driven by ONE pair (pymupdf on `4b31f0`, body 1210) whose first/last 20 rows are right but whose middle is fragmented. The gold cannot see mid-file damage, so that rule would make the width and fragment checks nearly vacuous. Not adopted.
- Split-word 0.02 and repeated-header 0.07 sit just above values seen on gold-accurate output (HIQA, FSPO hyphen/bullet text 0.015-0.020 split-word; a header repeating mid-page on `ec6c89` gives 0.06 with gold 1.00, since the gold excludes repeated headers). Purity unchanged at 0.85 (min over gold-accurate pairs 0.94).
- Width 0.92 / fragment 0.08: fail-closed choice. Relaxing below this admits camelot_lattice on `6ab587` (gold 0.07) and pymupdf on `494a78` (gold 0.22). Clean Fingal 2019-21 logs (width 0.93-0.949) still pass 0.92 on width.
- Cost: more gold-accurate pairs fail (see FN column), including FSPO `494a78` (width 0.90, fragment 0.10, a 9-row file, gold 0.98 for camelot_lattice, mistral, docling) and `4b31f0` (real mid-file fragmentation). Remaining FPs are mostly shifted-column or cell-text differences the label-free score cannot see; `passes` is not proof of correctness.
- Fingal sparse trailing column: the last column is empty in most rows, so `_trimmed` widths vary by row. Lowering width to 0.92 lets the 0.93-0.949 logs pass. A trim rule was NOT added: no clean Fingal 2019-21 gold file exists to validate it. Follow-up.
- Rests on 10 files with no holdout; re-run `bakeoff.py` + `report.py` when the gold set grows.

## Recommended candidate order and verdicts

- Docling: best mean gold accuracy (0.91, all 10 gold files) and highest pass rates, but it is a heavy dependency (torch + model weights downloaded from HuggingFace, 0.8-62 s per file). Free, offline once installed. Whether to adopt it as a production dependency is the user's call.
- Mistral (cache only): mean gold 0.88 on the 7 cached gold files only; extracts nothing for uncached files and fails repeated_header_share often (page headers not stripped), so it is not usable on the 12 of 36 sample files without a cache hit; paid OCR for the rest is the user's call.
- Among free geometric extractors: camelot_lattice has the best gold accuracy (0.76) and composite but finds no table on 5 of 36 files; pdfplumber (incumbent) 0.71; pymupdf 0.64 (pass counts above); camelot_stream is poor (pass 1/36).
