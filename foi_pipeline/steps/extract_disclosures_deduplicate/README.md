# extract_disclosures_deduplicate

Removes duplicate FOI disclosure records by treating `foi_reference_id` as a unique identifier per public body.

## What it does

PDF parsing often creates duplicate records due to:
1. Multi-line text splitting (long descriptions split across rows)
2. Same request appearing in multiple disclosure log files (e.g., quarterly and annual logs)

This step deduplicates records using a composite key of `(public_body_id, foi_reference_id)`.

- **First occurrence kept**: When duplicates are found, the first record encountered is kept (FIFO strategy)
- **Null IDs preserved**: Records with null/empty `foi_reference_id` cannot be deduplicated and are always kept
- **No data modification**: Records are only removed, never modified

`extract_disclosures_canonicalize/output.json` - Flat list of canonical FOI request records

## Notable files

- `process.py` - Main deduplication logic
- `errors.json` - Currently unused (no errors generated by this step)
- `__init__.py` - Empty module file

## Deduplication Behavior

| Scenario | Behavior |
|----------|----------|
| Same body, same ID | Keep first, remove subsequent |
| Same body, different ID | Keep both |
| Different body, same ID | Keep both |
| Null/empty ID | Always keep |

## Why a Composite Key?

We use `(public_body_id, foi_reference_id)` rather than just `foi_reference_id` because:

1. **FOI reference IDs are not globally unique** - Different departments may use similar ID formats (e.g., "2024-001")
2. **Within a single body, IDs should be unique** - Each request should have a distinct reference
3. **Prevents false collisions** - Avoids incorrectly removing records from different bodies that happen to share an ID

## Edge Cases

### Null/Empty Reference IDs
Approximately 68% of Department of Finance records have null `foi_reference_id`. These records:
- Cannot be deduplicated using the reference ID strategy
- Are always kept in the output
- Will require manual review or alternative deduplication methods in the future

### Continuation Rows
PDF parsing often splits long request descriptions across multiple rows. These appear as:
- Multiple records with the same `foi_reference_id`
- First row has the ID, subsequent rows have null/empty ID in first column
- The deduplication step removes the duplicate ID rows but keeps the null-ID continuation rows

*Note: A future enhancement could merge continuation rows back into single records.*

## Usage

Run the step directly:
```bash
cd foi_pipeline
PYTHONPATH=. python steps/extract_disclosures_deduplicate/process.py \
  --input steps/extract_disclosures_canonicalize/output.json \
  --output steps/extract_disclosures_deduplicate/output.json \
  --verbose
```

Or run via the orchestrator (recommended):
```bash
cd foi_pipeline
python orchestrator.py --from extract_disclosures_deduplicate --force
```

## Performance

The deduplication uses a simple Python `set` for O(1) lookups, making it efficient even for large datasets:
- Time complexity: O(n) where n is the number of records
- Space complexity: O(u) where u is the number of unique (body_id, ref_id) pairs
- Typical runtime: < 1 second for 70,000 records
