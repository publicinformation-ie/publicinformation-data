# foi_pipeline

The FOI pipeline finds Irish public bodies that are subject to FOI. It finds their FOI pages, contact emails and disclosure logs. It downloads the files that the logs link to and turns them into canonical (one fixed shape) FOI request records. This is the main pipeline in the repository. It publishes the `public-bodies` dataset.

The step order is in [`pipeline.json`](pipeline.json). Each step is in [`steps/`](steps/), and [`steps/README.md`](steps/README.md) lists the steps. This file explains how to run the pipeline and how to triage it. [`AGENTS.md`](AGENTS.md) explains the architecture, the dirty-state rules and the data flow.

## What a run produces

| Artifact | Contents |
|---|---|
| `steps/export_status/output.json` | Every body with its full status object (website, FOI page, FOI email, disclosure log, file counts and request count) |
| `public/pipeline-data.json` | The same consolidated status, published for the website |
| `public/disclosure-files.json` | A flat list of discovered disclosure file URLs |
| `public/latest/foi-disclosures/bodies/<public_body_id>.ndjson` | Canonical FOI request records, one file per body (committed, ordinary git) |
| `public/topics.json` | Topic groupings for FOI records |
| `public/latest/public-bodies/` | The public-bodies dataset, regenerated by `export_status` on a full run |
| libSQL tables | Filled by `db_upload` when database credentials are configured |

`export_status` also rebuilds the combined disclosure forms (JSON, CSV, JSON-LD and XLSX) and the bodies manifest from the per-body NDJSON files. These combined forms are not committed. The per-body files are the source of truth.

## Steps at a glance

- Discovery: [`resolve_website_urls`](../cso_pipeline/steps/resolve_website_urls/) (from `cso_pipeline`), then [`find_public_bodies`](steps/find_public_bodies/), [`find_public_bodies_subject_to_foi`](steps/find_public_bodies_subject_to_foi/), [`validate_websites`](steps/validate_websites/), [`find_foi_pages`](steps/find_foi_pages/), [`find_foi_pages_search`](steps/find_foi_pages_search/), [`check_foi_pages`](steps/check_foi_pages/), [`get_foi_emails`](steps/get_foi_emails/) and [`find_foi_email_pages`](steps/find_foi_email_pages/).
- Collection: [`find_disclosure_pages`](steps/find_disclosure_pages/), then [`fingerprint_disclosure_pages`](steps/fingerprint_disclosure_pages/), [`find_disclosure_files`](steps/find_disclosure_files/) and [`verify_disclosure_files`](steps/verify_disclosure_files/).
- Extraction: [`transform_disclosure_files`](steps/transform_disclosure_files/), then [`assess_table_structure`](steps/assess_table_structure/), [`normalize_disclosure_cells`](steps/normalize_disclosure_cells/), [`filter_phantom_rows`](steps/filter_phantom_rows/), [`extract_disclosures_detect_header_row`](steps/extract_disclosures_detect_header_row/), [`extract_disclosures_normalize_header`](steps/extract_disclosures_normalize_header/), [`extract_disclosures_split_combined_columns`](steps/extract_disclosures_split_combined_columns/) and [`extract_disclosures_normalize_rows`](steps/extract_disclosures_normalize_rows/).
- Canonicalization: [`extract_disclosures_canonicalize`](steps/extract_disclosures_canonicalize/), then [`extract_disclosures_canonicalize_rows`](steps/extract_disclosures_canonicalize_rows/) and [`extract_disclosures_deduplicate`](steps/extract_disclosures_deduplicate/).
- Publish: [`export_status`](steps/export_status/), then [`generate_topics`](steps/generate_topics/), [`db_upload`](steps/db_upload/) and [`sync_backlog`](steps/sync_backlog/).

The exact order is in [`pipeline.json`](pipeline.json). The order includes the `assess_table_structure` gate. This gate fails closed: when a PDF table has an unreliable structure, it writes no rows for that file.

## Running it

Run from the repo root and pass the pipeline directory. The shared runner uses the current working directory by default, not the script location.

```bash
# Full run
uv run python pipelines/foi_pipeline/process.py pipelines/foi_pipeline --force --stop-on-error

# Resume from a step, or run an inclusive window
uv run python pipelines/foi_pipeline/process.py pipelines/foi_pipeline --from export_status --force --stop-on-error
uv run python pipelines/foi_pipeline/process.py pipelines/foi_pipeline --from find_foi_pages --to get_foi_emails --force --stop-on-error

# One public body, end to end
uv run python pipelines/foi_pipeline/process.py pipelines/foi_pipeline --public-body 1001 --stop-on-error
```

`--public-body <id>` scopes a run to one body. It never forces a run, and it keeps the records for the other bodies. The pipeline defers the dirty IDs (body IDs that need a new run) for other bodies and reports them. Read [`AGENTS.md`](AGENTS.md#dirty-state-lifecycle-dirty_idsjson) before you rely on scoped runs.

### Network, paid steps and configuration

| Step | Requirement |
|---|---|
| `find_foi_pages_search` | `APIFY_TOKEN` (Apify credits) |
| `find_disclosure_pages` | `APIFY_TOKEN` for gov.ie bodies |
| `transform_disclosure_files` | Live Mistral OCR only with `--allow-paid-ocr`. The default is cache-only |
| `db_upload` | `.env.admin` with `DATABASE_URL` and `DATABASE_AUTH_TOKEN`. The step falls back to the local `local.db` |

`fingerprint_disclosure_pages` always runs, even when the pipeline skips other steps. It detects changes to disclosure pages between ordinary runs.

## OCR for disclosure PDFs

`transform_disclosure_files` extracts PDF tables with structure-based selection. Mistral OCR is cache-only by default. `mistral_cache` is one scored extractor candidate, and `ocr_cache/` holds the cached responses. Git LFS tracks the cache.

Live OCR is opt-in with `--allow-paid-ocr`. It requires `MISTRAL_API_KEY` and `MISTRAL_OCR_PDF_BASE_URL`. If either value is missing, the step raises `MistralConfigError` and does not fall back. You cannot combine live OCR with `--processes`. Read [`steps/transform_disclosure_files/README.md`](steps/transform_disclosure_files/README.md#mistral-ocr) for the cache format, the `skip_mistral` and `pdf_extractor` overrides, and the warning types.

## Tests and triage

```bash
# Step tests and evaluation
cd pipelines/foi_pipeline && uv run pytest tests/ -q

# Per-item view: completion, record counts, staleness and errors
cd pipelines/foi_pipeline && uv run python status.py

# Repo-wide status (from the repo root)
uv run python scripts/pipeline_status.py --pipeline foi_pipeline
```

A run with unresolved reconstruction errors needs a human review before publication. Read [`AGENTS.md`](AGENTS.md) for the data-handling rules and the `public/` publishing workflow.
