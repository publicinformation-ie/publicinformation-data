# PublicInfo Prototype - Data Consumption Documentation

This document explains how the publicinfo-prototype website consumes pipeline data and displays it on the data-status page.

## Overview

The publicinfo-prototype is an Astro-based static website that visualizes FOI (Freedom of Information) data for Irish public bodies. It consumes JSON data generated by the foi_pipeline and renders it as an interactive status table.

## Data Consumption

### Data Source

The website gets its data from:
```
publicinfo-prototype/src/data/pipeline-status.json
```

This file is **generated during the build process** by the prebuild script. It is NOT committed to git (except for a legacy version that was accidentally committed and should be cleaned up).

### Prebuild Script

Located in `package.json`:

```json
{
  "scripts": {
    "prebuild": "mkdir -p src/data && (cp ../foi_pipeline/steps/export_status/output.json src/data/pipeline-status.json 2>/dev/null || cp ../foi_pipeline/steps/find_public_bodies/output.json src/data/pipeline-status.json 2>/dev/null || echo '{\"metadata\": {}, \"public_bodies\": []}' > src/data/pipeline-status.json)"
  }
}
```

**Fallback Chain:**
1. **Primary**: `../foi_pipeline/steps/export_status/output.json` (preferred - has merged status from all steps)
2. **Fallback**: `../foi_pipeline/steps/find_public_bodies/output.json` (base data only)
3. **Final**: Empty JSON `{metadata: {}, public_bodies: []}` (graceful degradation)

This ensures the website always has *some* data, even if the pipeline hasn't been fully run.

### Build Process

When you run `npm run build` or `npm run dev`:

1. **prebuild** script runs first:
   - Creates `src/data/` directory if it doesn't exist
   - Copies the best available pipeline output to `pipeline-status.json`
   
2. **Astro build** runs:
   - Imports `pipeline-status.json` as ES module
   - Renders the data-status page with the data
   - Outputs static HTML to `dist/data-status/index.html`

## Data Status Page

### Page Location

```
publicinfo-prototype/src/pages/data-status.astro
```

This is an Astro page component that:
- Imports the Layout component
- Imports pipeline-status.json data
- Renders a table of all public bodies with their data completeness status

### Data Structure Expected

The page expects `pipeline-status.json` to have this structure:

```json
{
  "metadata": {
    "step": "export_status" | "find_public_bodies" | string,
    "completed_at": "2026-05-05T20:00:00.000000+00:00" | null
  },
  "public_bodies": [
    {
      "public_body_id": 1001,
      "name": "Department of Agriculture, Food and the Marine",
      "short_name": "DAFM",  // Optional - generated by export_status
      "official_website_url": "https://...",
      "status": {
        "website_url": {"url": "...", "status": "success" | "failed" | "not_attempted"},
        "foi_page": {"url": "..." | null, "status": "success" | "failed" | "not_attempted"},
        "foi_email": {"email": "..." | null, "status": "success" | "failed" | "not_attempted"},
        "disclosures_page": {"url": "..." | null, "status": "success" | "failed" | "not_attempted"},
        "disclosure_files": {"total": 0, "valid": 0, "failed": 0, "status": "success" | "failed" | "not_attempted"},
        "foi_requests": {"valid": 0, "errors": 0, "status": "not_attempted"}
      }
    }
  ]
}
```

### Field Usage

| Field | Required | Usage |
|-------|----------|-------|
| metadata.step | No | Debugging - shows which pipeline step generated the data |
| metadata.completed_at | No | Debugging - timestamp of data generation |
| public_body_id | Yes | Unique identifier for each body |
| name | Yes | Displayed as primary identifier |
| short_name | No | Displayed in parentheses after name, if present |
| official_website_url | Yes | Used for linking (future) |
| status.website_url | Yes | Website reachability status indicator |
| status.foi_page | Yes | FOI page discovery status indicator |
| status.foi_email | Yes | FOI email extraction status indicator |
| status.disclosures_page | Yes | Disclosures page discovery status indicator |
| status.disclosure_files | Yes | Disclosure files count and status |
| status.foi_requests | Yes | FOI requests count (future feature) |

### Status Value Rendering

The page uses Unicode characters to represent status:

| Status Value | Character | Color Class | Meaning |
|--------------|-----------|-------------|---------|
| "success" | ✓ (U+2713) | status-primary | Step completed successfully |
| "failed" | ✗ (U+2717) | status-refused | Step attempted but failed |
| "not_attempted" | — (U+2014) | status-grey-mid | Step not run or body not in results |

For `disclosure_files`, additional logic applies:
- total == 0: — (not attempted or no files found)
- failed == 0: ✓ (all files valid)
- valid == 0: ✗ (all files failed)
- otherwise: ! (U+0021) with color status-extension-granted (partial success)

For `foi_requests`, displays as `"valid/total"` (e.g., "85/90").

### Page Features

1. **Sorting**: Public bodies are sorted alphabetically by name
2. **Conditional Rendering**: short_name span only appears if short_name field exists
3. **Accessibility**: Each status cell has an aria-label describing the status
4. **Responsive**: Table layout adapts to screen size (via CSS)
5. **Hover States**: Table rows highlight on hover for better readability

## CSS Styles

Status table styles are in:
```
publicinfo-prototype/src/styles/global.css
```

Key classes:
- `.status-table` - Main table styling
- `.status-primary` - Green color (success)
- `.status-refused` - Red color (failed)
- `.status-grey-mid` - Grey color (not attempted)
- `.status-extension-granted` - Purple/orange color (partial)

## Troubleshooting

### Page shows no data (empty table)

**Cause**: prebuild script created empty pipeline-status.json

**Check**:
```bash
python3 -c "import json; data=json.load(open('publicinfo-prototype/src/data/pipeline-status.json')); print('Bodies:', len(data.get('public_bodies', [])))"
```

**Fix**:
1. Ensure export_status step has been run:
   ```bash
   cd foi_pipeline
   PYTHONPATH=. python steps/export_status/process.py \
     --input steps/find_public_bodies/output.json \
     --output steps/export_status/output.json \
     --force
   ```
2. Or ensure find_public_bodies/output.json exists (fallback)

### Page shows data but no short names

**Cause**: Using find_public_bodies output (fallback) which doesn't have short_name

**Check**:
```bash
python3 -c "import json; data=json.load(open('publicinfo-prototype/src/data/pipeline-status.json')); print('Step:', data['metadata'].get('step'))"
# If shows "find_public_bodies", that's the fallback
```

**Fix**: Run the export_status step to get short_name generation.

### Page shows data but all status are "—" (dashes)

**Cause**: Using find_public_bodies output which only has "not_attempted" for all status fields

**Check**:
```bash
python3 -c "import json; data=json.load(open('publicinfo-prototype/src/data/pipeline-status.json')); body=data['public_bodies'][0]; print('Website status:', body['status']['website_url']['status'])"
# If shows "not_attempted", other steps haven't been run
```

**Fix**: Run the other pipeline steps (validate_websites, find_foi_pages, etc.) and then export_status to merge the results.

### Build fails with JSON import error

**Cause**: pipeline-status.json is malformed or missing

**Check**:
```bash
python3 -c "import json; json.load(open('publicinfo-prototype/src/data/pipeline-status.json'))"
```

**Fix**: Ensure the file is valid JSON. Run the prebuild script manually:
```bash
cd publicinfo-prototype
mkdir -p src/data && (cp ../foi_pipeline/steps/export_status/output.json src/data/pipeline-status.json 2>/dev/null || cp ../foi_pipeline/steps/find_public_bodies/output.json src/data/pipeline-status.json 2>/dev/null || echo '{"metadata": {}, "public_bodies": []}' > src/data/pipeline-status.json)
```

## Data Freshness

The data-status page is **static** - it's built at compile time, not runtime. To update the data:

1. Run the pipeline to generate new outputs:
   ```bash
   cd foi_pipeline
   python orchestrator.py --force
   ```

2. Rebuild the website:
   ```bash
   cd publicinfo-prototype
   npm run build
   ```

The page will only show the data that was present at build time. For development with live-reloading, use `npm run dev` which will rebuild when files change.

## Integration Points

### With FOI Pipeline

- **Input**: Reads from `../foi_pipeline/steps/export_status/output.json` (preferred)
- **Fallback**: Reads from `../foi_pipeline/steps/find_public_bodies/output.json`
- **Relative Path**: Website must be in `publicinfo-prototype/` directory, pipeline in `../foi_pipeline/`

### Directory Structure

```
publicinformation-data/
├── foi_pipeline/
│   └── steps/
│       ├── find_public_bodies/
│       │   └── output.json          # Fallback data source
│       └── export_status/
│           └── output.json          # Preferred data source
└── publicinfo-prototype/
    └── src/
        └── data/
            └── pipeline-status.json  # Copied from pipeline (generated)
```
